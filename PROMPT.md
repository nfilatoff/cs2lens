# Задание для Codex: развитие cs2lens

Ты продолжаешь работу над проектом `cs2lens` в `D:\csdemoanalyzer` (Windows, Python 3.13, виртуальное окружение `.venv`). Это анализатор демок Counter-Strike 2. Сейчас это CLI. Нужно: (1) завести git, (2) настроить все карты соревновательного маппула CS2, (3) сделать полноценное приложение с 2D-реплеем раундов, (4) написать README. Работай поэтапно, после каждого этапа коммить, и не переходи к следующему, пока текущий не проверен на реальных демках.

## Что уже есть

Стек: `awpy==3.1.1` (парсер CS2 на Rust, сам по себе отдаёт rounds/kills/damages/shots/grenades/smokes/fires/blinds/bomb/item_events/stats/snapshots, а также `NavMesh`, `VisibilityChecker` и `awpy.plot`), `polars`, `matplotlib`, `typer`. Установка: `pip install -e .` (см. `pyproject.toml`).

Модули в `cs2lens/`:
- `extract.py`: `.dem` → `out/<имя демки>/*.parquet` (все датасеты awpy, все игровые события в `events/`, снапшоты игроков каждые 0.5 с) и `manifest.json` (header, tick_rate, число строк).
- `context.py`: `load_match()` загружает выгрузку и строит общий контекст: не-ножевые раунды, steamid→команда, сторона команды в каждом раунде (большинство по снапшотам), таблица `tr` (раунд × команда: сторона, победа, закуп). `with_round()` привязывает строки с `tick` к раунду.
- `team_stats.py`: командная статистика (сводка, стороны, закупы, причины побед, опенинги, трейды, бомба T/CT).
- `tactics.py`: экзекуты T (целевой сайт, старт экзекута, темп, пакет гранат), сетапы CT, ротации. Центры сайтов сейчас определяются как среднее мест плантов в демке, а все радиусы заданы долями расстояния A–B. Это эвристика, подобранная на de_anubis.
- `viz.py`: heatmap убийств, карта приземления гранат, кадр раунда, GIF-реплей (поверх `awpy.plot`). Многоуровневые карты рисуются только по верхнему уровню.
- `aggregate.py`: агрегация по нескольким матчам (суммы с пересчётом процентов, разбивка по картам, игроки, `--alias СТАРОЕ=НОВОЕ` для склейки названий команд).
- `report.py` (Markdown), `cli.py` (команды `extract`, `report`, `tactics`, `batch`, `viz kills|utility|frame|gif`).

Данные для проверки: выгрузки 6 матчей в `out/` (de_anubis ×2, de_ancient, de_dust2 ×2, de_inferno). Исходные демки 5 из них лежат в `D:\Steam\steamapps\common\Counter-Strike Global Offensive\game\csgo\*.dem`. Радарные картинки awpy кэширует в `~/.awpy/<версия>/`.

## Известные особенности данных (не сломай)

- В этих демках у гранат в `grenades`/`smokes`/`fires` пустой `thrower_*`. Бросающего восстанавливаем так: `events/weapon_fire.userid` построчно сопоставляется с `shots.steamid` (`tactics.userid_map`), а молотовы привязываются к последнему броску `grenade_thrown` перед возгоранием.
- У части демок пустой `rounds.start_tick` первого раунда (запись началась во время раунда). В `context.py` он заменяется на 0.
- События в `events/*.parquet` хранят все поля строками (x/y/z приходится приводить к числу).
- Шаг снапшотов 0.5 с (`Match.snap_step` в тиках), tick rate 64.
- В Windows-консоли при выводе на кириллице и спецсимволах нужно `PYTHONIOENCODING=utf-8`.

## Этап 2. Все карты соревновательного маппула

1. Сначала **проверь актуальный Active Duty маппул CS2** (он меняется с обновлениями) и выпиши его в README с датой проверки. Не полагайся на память. Кандидаты: de_ancient, de_anubis, de_dust2, de_inferno, de_mirage, de_nuke, de_overpass, de_train, de_vertigo. Также проверь, что для каждой карты есть радар и `map_data` в используемом релизе awpy-data.
2. Заведи конфиг карт (например, `cs2lens/maps/<map>.json` или один `maps.py`) для каждой карты пула:
   - **Бомбсайты:** полигоны в мировых координатах, а не только центры. Источник: зоны `func_bomb_target` или nav-области, отмеченные как сайт, если их можно достать. Иначе разметь вручную по радару и проверь по плантам из демок.
   - **Именованные зоны (callouts):** основные проходы и позиции (A main, B apps, mid, connector и т.д.) полигонами. Они нужны для сетапов CT, ротаций и описания экзекутов человеческим языком.
   - **Уровни:** для многоуровневых карт (Nuke, Train, Vertigo, если в пуле) границы по Z и отдельный нижний радар.
3. Перепиши `tactics.py` на конфиг: зона определяется попаданием точки в полигон с учётом уровня. Текущую эвристику (центры по плантам и доли расстояния A–B) оставь запасным вариантом для карт без конфига и пиши предупреждение, когда она используется.
4. `viz.py`: поддержи нижний уровень, то есть рисуй точки на нужном радаре, а для многоуровневых карт показывай две панели.
5. Проверка: для каждой карты пула, по которой есть демка, прогони `tactics` и визуально сверь зоны и точки на радаре. Если демок по карте нет, проверь хотя бы, что полигоны сайтов ложатся на сайты радара (отрисуй конфиг поверх радара командой вроде `cs2lens viz zones <map>`). Отдельно напиши, какие карты проверены на реальных демках, а какие только по разметке.

## Этап 3. Приложение с 2D-реплеем раундов

Нужно настоящее приложение, а не набор картинок. Предлагаемая архитектура (если видишь вариант лучше, обоснуй и спроси меня до начала работы):

- **Бэкенд:** FastAPI (Python) поверх существующих модулей `cs2lens`. Новый код аналитики не дублировать, только вызывать то, что есть.
- **Фронтенд:** React + TypeScript + Vite. Реплей рисовать на Canvas 2D или PixiJS. Запуск локально одной командой (например, `cs2lens app`), которая поднимает бэкенд и раздаёт собранный фронтенд.

Функции:
1. **Библиотека демок:** указать папку или загрузить `.dem`. Разбор идёт фоновой задачей с прогрессом, уже разобранные демки повторно не разбираются (кэш в `out/`).
2. **Страница матча:** счёт, команды, карта, ход матча по раундам (победитель, причина, закупы), командная статистика, статистика игроков, тактика.
3. **2D-реплей раунда:**
   - радар карты (с переключением уровней), игроки с именами, цветом стороны, направлением взгляда, HP и броней, активным оружием, бомбой;
   - гранаты в полёте с траекториями, смоки и молотовы с реальным временем жизни, флеши (кто ослеплён), плент и дефьюз;
   - киллфид, отметки убийств, плента и важных событий на таймлайне;
   - управление: play/pause, скорость (0.25×–8×), перемотка таймлайном, покадрово вперёд и назад, переход к следующему убийству, горячие клавиши;
   - плавность: 0.5 с снапшотов для реплея мало. Для реплея выгружай позиции чаще (каждые 4–8 тиков через `Demo.ticks`/`Demo.snapshots`) и интерполируй между кадрами на клиенте. Данные раунда готовь на бэкенде заранее и отдавай компактно (бинарный формат или JSON с массивами по игрокам), а не строками по одному тику.
4. **Карты:** heatmap убийств и смертей, карта гранат с фильтрами по команде, стороне, игроку и раунду.
5. **Несколько матчей:** выбрать набор демок, задать алиасы команд, посмотреть агрегированную статистику.

Требования: работает локально без интернета (кроме однократной загрузки радаров awpy, о которой нужно спросить меня), открывается в браузере, раунд в 2 минуты грузится в реплей быстро (ориентир — меньше 2 с на уже разобранной демке).

## Общие правила

- Пиши в стиле существующего кода: polars-выражения, type hints, docstring у публичных функций, комментарии только там, где неочевидно.
- CLI не ломай: все текущие команды должны продолжать работать. После каждого этапа прогоняй их на демках из `out/`.
- Добавь `pytest`-тесты на ключевую логику (привязка к раундам, стороны, агрегация: «одна демка дважды → счётчики ×2, проценты те же», попадание в зоны). Фикстуры делай из небольших срезов parquet, а не из демок.
- Ничего не скачивай и не устанавливай глобально без моего согласия. Зависимости добавляй в `pyproject.toml` и `package.json`.
- В конце каждого этапа коротко отчитайся: что сделано, как проверено, что не проверено, какие решения принял и почему.
